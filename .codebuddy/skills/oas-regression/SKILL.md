# OAS 防回归分析

## 适用场景

- 改完怕弄坏别的
- 准备合入上游更新前
- 定期体检

## 输入

改动清单，或空（全项目体检）。

## 第一步：算爆炸半径

**查符号，不是查文件。**

```bash
grep -rl "<符号名>" --include=*.py . | wc -l                    # 引用面
grep -rn "class ScriptTask(.*<组件名>" --include=*.py tasks/     # 继承方清单
```

## 第二步：对照已知高危清单

| # | 高危点 | 位置 | 触发条件 |
|---|---|---|---|
| 1 | **识别对象跨任务污染** | `assets.py` 2198 个单例 + `atom/image.py:178` `_apply_match_result()` 回写 `roi_front` | 同名素材被多任务使用 |
| 2 | 配置赋值即写盘 | `config_model.py:201` `__setattr__` | 循环内改配置 |
| 3 | 组件连锁 | `GeneralBattle` 33 任务 / `SwitchSoul` 32 任务 | 改共享组件 |
| 4 | 看门狗是类属性 | `device.py:29-33` | 给 Device 加状态 |
| 5 | 无退出条件的循环 | 440 处 `while True` | 改退出条件 |
| 6 | 吞异常 | 63 处，`AutoCheckinBigGod` 占 17 | 加 try/except |
| 7 | 点击放 `and` 左边 | 现存 5 处 | 写新条件判断 |
| 8 | **已知活 bug** | `tasks/GameUi/registry.py:82` `for module_name in ("page")` ← 字符串不是元组，遍历出 `'p','a','g','e'`，导致 **25 个 `tasks/*/page.py` 永不被 `load_all_pages()` 加载** | 动 GameUi 时必须确认 |

> 第 8 条是**当前项目确实存在的活 bug**。修复只需加一个逗号，但 25 个 `page.py` 突然全部加载可能引发重名冲突 → **必须实测**。

## 第三步：列出必须回归的任务

| 改了什么 | 至少测什么 |
|---|---|
| `GeneralBattle` | ≥3 个继承它的任务 |
| `SwitchSoul` | ≥3 个继承它的任务 |
| `GameUi` / 页面导航 | 跨玩法跳转 |
| 识别素材 | **所有**用到同名 `I_XXX` / `O_XXX` 的任务 |
| `config_model.py` | 任取 2 个任务确认配置能读 |
| Device / 截图 | 1 个稳定玩法跑完整一轮 |

## 第四步：给出回归测试顺序

先测**最常用、最贵**的玩法（失败代价高的排前面），再测边缘玩法。

## 常见错误

- 只测改动直接对应的那一个玩法
- 忘了"同名素材跨任务共享"这一层（第 1 号高危点）
- 用"代码看着没问题"代替实测
- 改了 A/B 级却不列回归清单

## 禁止事项

- 改动 A/B 级后不列回归清单
- 用静态检查冒充回归测试
- 说"影响很小不需要测"而不给出依据

## 完成后输出

```
受影响任务清单（grep 出的实数）
建议测试顺序
未验证项
```

若一项都没测 → 明确写"**本次改动零实机验证**"。
