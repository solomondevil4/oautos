# 附：已完成的真实例子（供对照格式）

## 【问题】
跨玩法页面跳转绕远路或失败；本玩法自己的页面正常，但跳到别的玩法的页面时常失败。

## 【相关文件】
- `tasks/GameUi/registry.py:82` —— 页面注册表的模块遍历逻辑
- `tasks/<玩法>/page.py` × 25 个 —— 各玩法自己声明的页面与跳转边

## 【调用链】
```
load_all_pages() → registry.py:82 for module_name in ("page") → import tasks.<X>.<module_name>
```

## 【当前行为】
`("page")` 是**字符串不是元组**（缺逗号），遍历得到 `'p','a','g','e'` 四个字符，
于是去找 `p.py` / `a.py` / `g.py` / `e.py`，全部不存在 → 25 个 `page.py` 永远不被导入。

## 【预期行为】
遍历 `("page",)` 这个单元素元组，导入每个 `tasks/<X>/page.py`。

## 【根本原因】
Python 单元素元组漏写逗号。`("page")` 求值为字符串而非元组。

## 【hurry2实现】
**未修**，bug 仍存在于 `5567a78c`。本玩法自己的页面因 `script_task.py` 直接 import 而不受影响，
所以问题只表现为"跨玩法跳转异常"，不易被发现。

## 【AzurTian / runhey 参考】
runhey 在 `3a6e56c2`（2026-09-19）已修。AzurTian 是 Hurry2 的下游，不需参考。
结论：**可合**（只加一个逗号，属 bug 修复，不是架构改动）。

## 【推荐方案】

| 方案 | 改几行 | 碰哪些文件（级别） | 风险 | 副作用 |
|---|---|---|---|---|
| A：加逗号 | 1 行 | `registry.py`（🟠 B 级） | 低 | 25 个 page.py 突然全部加载，**可能引发页面名重名冲突** |
| B：不改 | 0 行 | 无 | 无 | 跨玩法跳转继续异常 |

**选择**：方案 A —— 改动最小（1 行）；但必须先实测确认无重名冲突。
